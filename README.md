## Данные: GTSRB (дорожные знаки)

**GTSRB — German Traffic Sign Recognition Benchmark**: соревнование по классификации знаков на IJCNN 2011 (Stallkamp, Schlipsing, Salmen, Igel; Рурский университет Бохума). Реальные фотографии знаков, снятые с автомобиля, в разных погодных и световых условиях.

- 43 класса (ограничения скорости, запреты, предупреждения, предписания).
- Версия, которую скачивает `torchvision`: **26 640 изображений train** (888 треков по ~30 кадров одного знака, от 150 до 1 500 изображений на класс) и **12 630 test**. Оригинальный конкурс заявляет 39 209 train, но фактически в загружаемом архиве `GTSRB-Training_fixed.zip` лежит 26 640.
- Цветные `.ppm`, стороны по описанию конкурса от ~15 до ~250 px, в загруженной версии (выборка) от 25 до 134 px, медиана 39; в ноутбуке приводятся к 64×64.
- Сильный дисбаланс классов (10 : 1): кроме accuracy считается macro-F1.
- Кадры одного трека почти идентичны, поэтому validation вырезается из train **группами по треку** (иначе утечка).
- Горизонтальное отражение как аугментация не используется: оно меняет смысл знаков.

Официальная страница: <https://benchmark.ini.rub.de/> (при подготовке лабораторной она не открывалась; зеркало: Zenodo, DOI 10.5281/zenodo.13741936). Явная свободная лицензия на странице зеркала не указана, датасет создан для исследований: если собираетесь публиковать данные, проверьте условия на официальной странице. Ссылка: J. Stallkamp, M. Schlipsing, J. Salmen, C. Igel. *The German Traffic Sign Recognition Benchmark: A multi-class classification competition.* IJCNN 2011.

Данные скачиваются автоматически при первом запуске ноутбука через `torchvision.datasets.GTSRB(download=True)` в папку `data/` (≈280 МБ архивов, ≈700 МБ после распаковки). Интернет нужен для первого запуска.

## Запуск в Jupyter

Рекомендуется Python 3.13 (проверено на 3.13.7). Все команды — из папки `lab2_home_deepML`.

### Окружение уже создано (на этом компьютере)

```bash
source .venv/bin/activate
python -m jupyterlab lab2_cnn.ipynb
```

### Чистая установка (другой компьютер или если `.venv` нет)

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --sys-prefix --name lab2 --display-name "Python (lab2)"
python -m jupyterlab lab2_cnn.ipynb
```

В JupyterLab выберите ядро **Python (lab2)** и выполните **Kernel → Restart Kernel and Run All Cells**. Дождитесь окончания всех ячеек и сохраните ноутбук (Ctrl/Cmd+S). Заново запускать обучение необязательно: сохранённые прогоны подхватываются автоматически (`results/history_*.csv` и веса в `.cache/ckpt`), поэтому повторный запуск с готовыми результатами занимает минуты. Чтобы обучить всё заново, удалите `results/history_*.csv`.

Другие способы:
- Запуск из терминала без интерфейса (в активированном `.venv`; выполняет ноутбук и сохраняет результаты в нём):

Устройство выбирается автоматически: `cuda`, затем `mps` (GPU Apple Silicon), затем `cpu`. На CPU обучение заметно медленнее. Не перемещайте ноутбук отдельно от папок `data`, `results`.

## Основные результаты

Подробности и графики — в ноутбуке и в `results/` (`conclusions.md`).

| Модель | Параметров | Val macro-F1 | Test accuracy | Test macro-F1 |
|---|---|---|---|---|
| Константный прогноз | 0 | 0.002 | — | — |
| MLP | 6.4 млн | 0.762 | 0.830 | 0.770 |
| Своя CNN (max-pooling, seed 42) | 0.92 млн | 0.969 | 0.985 | 0.978 |
| AlexNet с нуля (вход 224) | 57.2 млн | 0.954 | 0.969 | 0.950 |
| AlexNet fine-tuning (вход 224) | 44.5 млн | 0.948 | 0.966 | 0.955 |

- Пулинги (3 seed, val macro-F1): max 0.963 ± 0.005, average 0.953 ± 0.000; разница около двух разбросов seed, поэтому преимущество max не доказано.
- Вход AlexNet (val macro-F1, 64 -> 224): с нуля 0.750 -> 0.954, fine-tuning 0.635 -> 0.948.
- Fine-tuning не дал заметного выигрыша над обучением с нуля на 224 px (val 0.948 против 0.954; test 0.955 против 0.950).
- Пункт 3: замена 93×93 стопкой из 46 слоёв 3×3 даёт сокращение параметров в 7.1 раза, замена 60×60 (2×2 + 29 слоёв 3×3) — в 4.6 раза, k3=0 не определён. Это теоретический расчёт.
- Test оценивался один раз после выбора моделей по validation. Выбор seed и размера входа AlexNet делался по validation.

## Методика

- Разбиение: официальный test (12 630) используется один раз в конце. Из train (26 640) вырезается validation (≈20%) через `StratifiedGroupKFold` по группам «класс + трек». Нормализация считается только по train.
- Модели: константный прогноз, MLP, своя CNN (≈0.9 млн параметров), AlexNet с нуля (≈57 млн), AlexNet fine-tuning (предобученная `IMAGENET1K_V1`, заменены последние линейные слои).
- Обучение: AdamW, косинусный scheduler, аугментации на устройстве (поворот ±10°, сдвиг, масштаб, яркость, контраст; без отражений), early stopping по validation macro-F1 с восстановлением лучшей эпохи.
- Метрики: accuracy и macro-F1; для лучшей модели — матрица ошибок и худшие классы.
- Seed: три (42–44) для сравнения пулингов, один (42) для остальных моделей.
- Вход: данные хранятся и подаются в свои модели как 64×64. AlexNet получает изображения, **увеличенные внутри модели до 224×224** (размер оригинальной AlexNet): на 64×64 её `features` схлопывают карту до 1×1, и fine-tuning на 64×64 оказался хуже обучения с нуля. Прогоны на 64×64 оставлены в ноутбуке для сравнения (раздел 7.4).

## Ограничения

Один фиксированный split train/validation; один seed для AlexNet и fine-tuning; AlexNet работает на увеличенных с 64 до 224 изображениях (новых деталей это не добавляет), гиперпараметры AlexNet не подбирались; многократный выбор по validation может слегка завышать его оценку; все знаки немецкие; метрики train скользящие (с аугментацией и Dropout). Расчёт пункта 3 для ядер 93 и 60 теоретический.
